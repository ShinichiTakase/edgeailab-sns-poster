# 内部仕様: URLをコメント（返信）に書く機能

## 目的
- Instagramリール・Facebookリール: 動画の下の「詳細はプロフィールのリンクから」をやめ、
  公開後のコメントに「詳細は、{URL}をご覧ください」を書き込む。
  動画の下の文言は「詳細は、コメントのURLをご覧ください」（`videoGenerator.js` の `FOOTER_TEXT`）。
- Threads: 本文にURLがある場合は本文から外し、返信に「詳細は、{URL}をご覧ください」を書き込む。

## 実装
- `src/lib/linkComment.js`: コメント・返信の送信部品。
  - Instagram: `POST graph.instagram.com/v26.0/{media-id}/comments`（`instagram_business_manage_comments`、連携済み）
  - Facebook: `POST graph.facebook.com/v26.0/{video-id}/comments`（Page token。`pages_manage_engagement` が必要）
  - Threads: `POST graph.threads.net/v1.0/{user-id}/threads`（`reply_to_id`）→ `threads_publish`
    （`threads_manage_replies` が必要）
- `scheduledPostExecutor.js` の `postToPlatform` が、投稿成功後に呼ぶ。
  - **コメントの失敗は投稿の成否に影響させない**（`logger.logError` に記録するのみ）。
  - コメントするURLは `lifecycle.linkUrl`（= 予約の `link_url`）。無ければコメントしない。
- 動画の下の文言: `renderVideo({ footerText })`。空文字なら表示しない。
  URL指定でAI生成したときだけ表示する（`videoGenerationJobStore.js`）。再作成は `hasLink: true` のときだけ。

## Threadsの有効化スイッチ
- 環境変数 `THREADS_URL_REPLY_ENABLED=1` のときだけ、URLを本文から外して返信に移す。既定は無効。
- 理由: 顧客が `threads_manage_replies` を付与し直す前に有効にすると、URLが本文から消えて
  返信も付かない投稿になるため。

## Meta側の準備（本番）
- Facebook: ユースケースと「ビジネス向けFacebookログイン」の設定（`FACEBOOK_CONFIG_ID`）に
  `pages_manage_engagement` を追加。既存顧客はFacebookの再連携が必要。
  - **`pages_read_user_content` も必要**（2026-11-07、本番とグラフAPIエクスプローラで確認）。
    リールの動画IDへの `POST /{video-id}/comments` は、`pages_manage_engagement` だけでは
    `(#200) The permission(s) pages_read_user_content are not available` で失敗する
    （ユースケースに未追加の間）。ユースケースに追加し、設定にも足し、顧客は再連携する。
    アプリの役割のない一般顧客に使うには、Meta の審査（高度なアクセス）が必要になる可能性がある（未確認）。
  - 連携の確認画面で「以前の設定を引き継ぐ」が出たら「設定を編集」で、新しい許可がオンかを確認する。
- Threads: `threads_manage_replies` を追加し、`src/routes/threads.js` の `SCOPE` に足す。
  既存顧客はThreadsの再連携が必要。
- 審査（高度なアクセス）の要否は、Meta側の最新の資料で確認すること（未確認）。

## URLの保存（マイグレーション 007）
- `schedule_texts.link_url` と `scheduled_posts.link_url`（どちらもNULL可）を追加（`007_link_url.sql`）。
  ロールバックは、URLが保存されている間は拒否する（`007_link_url.down.sql`）。
- 実行時にスキーマ007以上を要求する（`dataSource.js`）。**本番に出すときは、007の適用が先**
  （バックアップ取得・マイグレーションの承認が別途必要）。
- 流れ: 登録画面のURL入力欄 → 文章保存時に `linkUrl`（`POST .../texts/bulk` はバッチ単位、
  `POST .../texts` と `PATCH .../texts/:id` は1件単位）→ `schedule_texts.link_url`
  → 予約生成（`scheduleMaterializer.js`、Instagram・Facebookリールのみ）→ `scheduled_posts.link_url`
  → 投稿時 `lifecycle.linkUrl`。
- URLはhttp(s)のみ・1000文字以内（`isValidLinkUrl`）。不正なら `link_url_invalid`（400）。
- PATCHで `linkUrl` を指定しなければ、保存済みのURLは変えない。
