# 内部仕様: ログアウト

最終更新日: 2026-08-22
コード参照: sns-poster/src/routes/auth.js（POST /api/auth/logout）, sns-poster/src/lib/jwt.js

## APIエンドポイント

| メソッド | パス | 認証 | 概要 |
|---|---|---|---|
| POST | /api/auth/logout | 不要 | セッションCookieのクリア |

## 処理内容

```js
router.post("/api/auth/logout", (req, res) => {
  clearSessionCookie(res);
  res.json({ ok: true });
});
```

`clearSessionCookie`（jwt.js）は`res.clearCookie(COOKIE_NAME, { path: "/" })`を実行する
のみ。認証チェック（requireAuth）を経由しないため、未ログイン状態で呼んでもエラーには
ならない。

## サーバー側セッションストアが存在しない点について

本システムはステートレスJWT方式（express-session等を使わない）であるため、
「特定の1セッションだけを個別に失効させる」手段がそもそも存在しない。ログアウトは
あくまでブラウザ側のCookieを削除するだけの操作であり、JWT自体（トークン文字列）は
有効期限（30日）まで理論上有効なままである。

全セッションを一括で強制的に失効させたい場合（パスワード変更・パスワード再設定・
メンバー削除・解約等）は、`users[].sessionVersion`をインクリメントする別の仕組みを使う
（各機能の内部仕様参照）。通常のログアウト操作ではこの`sessionVersion`は変更されない。

## 外部SaaS連携

なし

## microCMSスキーマへのI/O

なし（Cookie操作のみで、customersレコードへの読み書きは発生しない）

## エッジケース

- ログアウトAPIが何らかの理由で失敗しても、後続のフロント側処理（login.htmlへの遷移）は
  影響を受けない設計（外部仕様参照）
- 理論上、ログアウト後もCookie削除前にコピーされたJWT文字列（ブラウザの開発者ツール等で
  抜き出された場合）は、有効期限内・sessionVersion一致であれば別のクライアントから
  引き続き使用可能である（httpOnly Cookie自体はJSからの読み取りはできないが、
  Cookie値そのものの盗用に対する対策ではない旨は一般的なJWT運用の制約として留意）
