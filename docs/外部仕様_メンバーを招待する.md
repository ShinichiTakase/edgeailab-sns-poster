# 外部仕様: メンバーを招待する

最終更新日: 2026-08-24（更新: 招待承諾画面のパスワード要件表示をリアルタイム
チェックリスト形式に統一）
コード参照: team.html, accept-invitation.html

## メンバー一覧画面（team.html）

見出し「メンバー」、リード文「チームメンバーの一覧と、新しいメンバーの招待を行います。
役割ごとに操作できる範囲が異なります。」

### メンバー一覧テーブル

列: 氏名 / メールアドレス / 役割 / 状態 / 操作。メンバーがいない場合「メンバーはまだ
いません。」を表示。

- 状態表示: サーバー値「招待中」はそのまま「招待中」、「承諾済み」は「参加済み」という
  ラベルで表示される（内部ステータス名と画面表示名が異なる点に注意）
- 削除ボタン: **アカウント作成者（最上位の権利者）の行には表示されない**（誤操作防止）。
  さらに**管理者ロールのユーザーにしか表示されない**（サーバー側でも同一制約を再検証）

### 「メンバーを招待する」ボタン

管理者以外のロールでは非活性化され、ツールチップ「メンバーの招待には管理者権限が
必要です」が表示される。

### 招待モーダル

タイトル「メンバーを招待する」。入力項目:
- 氏名（必須）
- メールアドレス（必須）
- 役割（セレクト。選択肢は **管理者・承認者・編集者・閲覧者** の4つ、初期値は管理者）
- 承認者（役割を「編集者」にした場合のみ表示・必須。ラベル「承認者（1人以上選択）」。
  候補は「既に招待を承諾済みで、役割が管理者または承認者」のメンバーのみ。候補がいない場合
  「承認者に指定できるメンバー（管理者・承認者）がまだいません。」と表示

ボタン: 「キャンセル」（押下でdashboard.htmlへ遷移）／「送信」（送信中は「送信中...」）

### 招待送信のエラーメッセージ

| エラーコード | 表示文言 |
|---|---|
| invalid_email | メールアドレスの形式が正しくありません。 |
| invalid_name | 氏名を入力してください。 |
| invalid_role | 役割を選択してください。 |
| approver_required | 承認者を1人以上選択してください。 |
| invalid_approver | 選択された承認者に無効なメンバーが含まれています。 |
| already_member | 既にメンバーです。 |
| forbidden | 招待の送信には管理者権限が必要です。 |
| email_not_verified | メール認証が完了していません。 |
| member_limit_reached | ご利用中のプランのユーザー数上限に達しています。プランのアップグレードが必要です。 |
| （その他） | 招待の送信に失敗しました。しばらくしてから再度お試しください。 |
| 通信エラー | 通信エラーが発生しました。しばらくしてから再度お試しください。 |

成功時はモーダルを閉じ一覧を再読み込みするのみで、明示的な成功メッセージは表示されない。

## プラン別ユーザー数上限（2026-08-22実装）

新規招待（既存のpending招待への再送信は対象外）が以下の上限に達している場合、
`member_limit_reached`エラーになり招待できない。上限は招待中・参加済みを問わず
`users`配列の要素数（アカウント作成者本人を含む）で判定する。

| プラン | 上限人数 |
|---|---|
| Basic | 1名 |
| Standard | 3名 |
| Advanced | 3名 |

pricing.html記載の「ユーザー（管理者）数上限」と一致させている。**2026-08-22までは
この上限チェック自体が実装されておらず、Basicプランでも人数無制限に招待できて
しまっていた**（FAQ整備時の実装レビューで発覚し、pricing.htmlの記載に合わせて
実装した）。

### 再送信（再招待）について

画面上に専用の「再送信」ボタンは存在しない。招待中（未承諾）の相手に対しては、
同じメールアドレスで招待モーダルから再度招待操作を行うことで、実質的な再送信となる
（トークンが再発行される。内部仕様参照）。

### メンバー削除モーダル

タイトル「メンバーの削除」。本文「{氏名}様（{メールアドレス}）を削除しますか？
削除すると、このメンバーはログイン・操作ができなくなります。」

| エラーコード | 表示文言 |
|---|---|
| owner_cannot_be_removed | アカウント作成者は削除できません。 |
| member_not_found | 対象のメンバーが見つかりませんでした。 |
| forbidden | メンバーの削除には管理者権限が必要です。 |
| （その他） | 削除に失敗しました。しばらくしてから再度お試しください。 |
| 通信エラー | 通信エラーが発生しました。しばらくしてから再度お試しください。 |

## 招待承諾画面（accept-invitation.html）

招待メールのリンク（`?token=`）からのみアクセスする想定の画面。

- トークン欠如時: 「招待リンクが正しくありません。」（フォーム非表示）
- トークン有効性確認結果によるエラー
  - `expired_token`: 「招待の有効期限が切れています。招待者に再送を依頼してください。」
  - `already_accepted`: 「この招待は既に承諾済みです。ログインしてご利用ください。」
  - その他: 「招待リンクが正しくないか、期限切れです。」
  - 通信エラー: 「通信エラーが発生しました。しばらくしてから再度お試しください。」
- 有効な場合、招待内容を表示: 「**{メールアドレス}** 様／ロール: {役割}／{会社名（あれば）}」
- 入力項目: パスワード、パスワード（確認用）
  - パスワード欄の下に、入力に応じてリアルタイムで更新される要件チェックリストを表示
    （2026-08-24変更: 静的な案内文「半角英字・数字・記号をすべて含む8文字以上で
    設定してください。」から、パスワード再設定画面と同じスタイル――条件を満たす
    たびに緑色でチェック「レ」が付く4項目リスト（半角英字が1文字以上／数字が1文字
    以上／記号が1文字以上／8文字以上）――に統一。**要件そのものは変更していない**
    （英大文字・小文字の区別は無く「英字1文字以上」のまま。パスワード変更画面の
    5項目・大文字小文字別判定とは要件セットが異なる点に注意。統一したのは表示
    スタイルのみ）
- 送信ボタン「パスワードを設定して承諾する」（送信中「処理中...」）
- バリデーション順序: まずパスワード一致確認（不一致「入力されたパスワードが一致しません。」）、
  次に要件確認（未達「パスワードは半角英字・数字・記号をすべて含む8文字以上で入力
  してください。」）
- 承諾成功時: `dashboard.html`へ遷移（この時点で自動的にログイン状態になる）
- サーバー側エラー
  - `expired_token`: 「招待の有効期限が切れています。招待者に再送を依頼してください。」
  - `already_accepted`: 「この招待は既に承諾済みです。ログインしてください。」
  - `invalid_password`: 「パスワードは半角英字・数字・記号をすべて含む8文字以上で
    入力してください。」
  - その他: 「承諾に失敗しました。しばらくしてから再度お試しください。」

## ロール体系（4種類）

| ロール | 概要（招待モーダル上の並び順） |
|---|---|
| 管理者 | 最上位権限。メンバー招待・削除、解約等の操作が可能。承認者候補になれる |
| 承認者 | 編集者が作成した投稿内容の承認・却下ができる。承認者候補になれる |
| 編集者 | 投稿内容の作成はできるが、直接保存はできず承認者への承認依頼が必須 |
| 閲覧者 | 閲覧のみ（要確認: 書き込み制限の実装状況は内部仕様参照） |

サインアップした本人（アカウント作成者）は自動的に「管理者」ロールで登録される。

## 要確認事項

- 承諾済み・招待中いずれの状態でも「役割」表示はそのままの値が出るが、状態ラベルのみ
  「承諾済み→参加済み」という表示名変換がある。用語統一（画面上「参加済み」、内部的には
  「承諾済み」）は意図的な仕様と思われるが、他画面での用語不統一が無いか要確認
